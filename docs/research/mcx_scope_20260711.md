# MCX Commodity Scope — Verified Findings (2026-07-11)

**Status:** Investigation complete, verified against live external documentation
(not just this codebase). Supersedes `mcx_scope_20260710.md`, whose §2 open
questions are now answered — all negatively for a free/no-cost data path.
**Trigger:** A follow-up task specified a full MCX tool suite (symbol resolution,
option chain, dashboard, market_awareness, benchmark divergence). Before writing
any code against assumed API access, every data-source assumption was checked
directly against the vendors' own current public documentation.

---

## 1. No free, working API path to real MCX quotes/option-chain/instrument data exists

### Zerodha (`src/broker/zerodha_web.py`, `src/broker/jugaad.py`)

`ZerodhaWebClient` authenticates against `kite.zerodha.com`'s internal web-app API
(the same one the Kite web UI uses) via an `enctoken` cookie — **not** the official
Kite Connect REST API (`api.kite.trade`), which requires a paid subscription this
account does not have (per `CLAUDE.md`: "No Kite Connect subscription"). This
client exposes `orders`/`positions`/`margins`/`trades` only — no quote, no
instrument list, no historical-candle endpoint of any kind. `jugaad-trader` (the
fallback client) mirrors `kiteconnect`'s interface shape (`kite.profile()`,
`kite.set_access_token()`) but its own PyPI docs describe only login/order/
holdings/margins — no historical-data method is documented anywhere for it either.

Confirmed via Kite's own developer forum (`kite.trade/forum/discussion/8431`):
**"Kite Connect provides real-time data for NSE, BSE, and MCX"** — MCX access is
real, but only through the paid Kite Connect product, not the free web-scraping
approach this repo uses. The same thread confirms Kite Connect provides *futures
and options contract quotes* for MCX (e.g. `GOLD20OCTFUT`), not raw commodity spot
prices — spot/benchmark prices would still need an external source regardless.

### INDmoney / INDstocks (`src/brokers/indmoney.py`)

Checked directly against `api-docs.indstocks.com` (their current public docs):
- `/market/instruments`'s `source` query parameter has a documented enum of
  **`equity | fno | index` only** — no MCX or commodity value exists.
- `/market/quotes/full` and `/market/historical/{interval}` examples only show
  `NSE_` and `NFO_` exchange-segment prefixes (e.g. `NSE_3045`, `NFO_51011`) — no
  MCX examples or segment prefix documented.
- `/option-chain` and `/option-chain-symbols` are **officially still "Coming
  Soon"** — verbatim: *"All option chain and Greeks APIs are currently under
  development and will be available soon."* This matches the hardcoded stub
  already in `src/brokers/indmoney.py::get_option_chain`
  (`{"status": "not_available", "message": "Option chain coming soon in
  INDstocks API"}`) exactly — the stub is accurate, not stale.
- The API overview page's own multi-exchange claim reads **"NSE, BSE"** — MCX is
  not listed as a supported exchange anywhere in their current public docs,
  contradicting the assumption (from the task spec) that INDstocks documents
  "multi-exchange support (NSE, BSE, MCX)."

There is also **no `lookup_ind_keys` function or endpoint** documented anywhere in
INDstocks' public API reference or in this codebase — confirmed again this pass.

### MCX India's own data feed

`mcxindia.com/technology/datafeed` describes a **paid, B2B, subscription-based**
data feed: submit a request form, sign a data-feed agreement, pay, then receive
feed access/specification. There is no free public developer API from the
exchange itself.

### Third-party free APIs / MCP servers

Searched broadly (WebSearch) for any free developer API or Claude-compatible MCP
server with real MCX/Indian-commodity coverage. Every result was a **consumer-
facing website** (NiftyTrader, Groww, Dhan, Quintal Mind, MCX's own site) — none
expose a documented, free, programmatic API. No MCP server with real MCX coverage
was found; the closest candidate (`github.com/OilpriceAPI/mcp-server`, MIT
licensed) wraps **oilpriceapi.com**, which covers 70+ **international** benchmark
commodities (WTI, Brent, Henry Hub, gold, etc.) — genuinely useful as an
international benchmark source (see §2), but has zero MCX/Indian-exchange data.

## 2. What this pass actually built: benchmark side only

`check_benchmark_divergence` (`src/tools/mcx.py`, `src/mcx/benchmark.py`,
`src/mcx/benchmark_sources.py`) is a real, working tool for the **international
benchmark half** of a divergence check — WTI (crude) and Henry Hub (natural gas)
via OilPriceAPI's free tier (`GET /v1/prices/latest?by_code=WTI_USD` /
`by_code=NATURAL_GAS_USD`, optional `OILPRICEAPI_KEY`). Since there is no working
MCX-side price source (per §1), the tool takes the MCX contract's own % change as
an explicit caller-supplied parameter rather than fetching it — an honest scope: it
does the one real thing it can (compare a given number against a real external
benchmark), rather than faking the other half.

## 3. What would unblock full MCX symbol/quote/option-chain/dashboard parity

Either of:
1. **A Kite Connect subscription** (paid, ~₹2000/month at time of writing per
   public Zerodha pricing — verify current pricing before committing) plus MCX
   commodity-segment trading permission activated on the account. This is the
   only path confirmed by Zerodha's own forum to provide real MCX quotes/
   instrument data/futures-option chain access.
2. **A different paid data vendor** with confirmed Indian commodity-exchange
   (MCX) coverage — none was found with a free tier in this investigation.

Until one of these is in place, do not add placeholder/stub MCX symbol-resolution,
option-chain, or dashboard tools — a tool that can never return real data invites
false confidence and is worse than no tool. Revisit this doc once either path above
is actually available, and design against the real, confirmed response shapes at
that time rather than the assumptions in the original task spec (which claimed
INDstocks MCX support that does not exist in their current public API).
