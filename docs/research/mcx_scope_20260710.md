# MCX Commodity Scope — Investigation Findings (2026-07-10)

**Status:** Investigation only — no implementation in this pass.
**Trigger:** Trading CRUDEOILM and NATGASMINI on 2026-07-10 required manual app
use; neither the Zerodha wrapper nor the INDmoney wrapper in this codebase
expose MCX instrument lookup, quotes, or orders today.

---

## 1. Current state in this codebase

Confirmed by direct code search — no `exchange="MCX"` handling exists anywhere:

- `src/broker/zerodha_web.py` and `src/broker/jugaad.py` (the two `BrokerClient`
  implementations used by `require_broker()`) have no `exchange` parameter on
  `orders()`, `positions()`, `margins()`, `trades()`, or any quote/historical
  method. Kite Connect's REST API does accept an `exchange` field on the order
  placement/quote endpoints (per public Kite Connect docs — not verified
  against a live account in this pass), but nothing in this repo's broker
  layer currently threads it through.
- `src/chart_awareness/data_fetcher.py::_to_zerodha_symbol()` hardcodes NSE/BSE
  aliases only (`NSE:`, `BSE:` prefixes) — no MCX branch, no commodity symbol
  table (CRUDEOIL, NATURALGAS, GOLD, SILVER futures/options naming).
- `src/brokers/indmoney.py` (the INDstocks-backed adapter) only ever
  constructs/reads `exchange_segment` values shaped like `"NSE_EQ"` — every
  observed call site strips the `_EQ`/`_FO` suffix and defaults to `"NSE"`.
  There is **no `lookup_ind_keys` function or `filter_type` parameter
  anywhere in this codebase** — that name does not correspond to any existing
  code here. It may be a documented INDstocks REST endpoint not yet wrapped,
  but that must be verified against INDstocks' own API reference, not assumed
  from this repo.
- `MonitorPosition`/`MonitorInstrumentCache` (`src/db/models.py`) both have a
  free-text `exchange` column, currently only ever populated with `"NSE"`
  (default) or `"BSE"` (SENSEX/BANKEX paths). Nothing in the schema
  constrains this column to a fixed enum — no CHECK constraint was found —
  so adding `"MCX"` as a value is schema-compatible with zero migration.

## 2. What still needs external verification (not done in this pass)

1. **Kite Connect commodity segment access.** Kite Connect's public API
   documentation (kite.trade) describes MCX as a supported `exchange` value
   for `orders`, `quote`, and `historical_data` endpoints, gated by a
   separate **commodity trading permission** on the underlying Zerodha
   account (distinct from the equity/F&O segment activation) — this needs to
   be confirmed against the actual account this MCP authenticates as, since
   segment access is account-specific and can't be verified from code alone.
2. **INDstocks API commodity coverage.** The task's premise — that INDstocks
   documents "multi-exchange support (NSE, BSE, MCX)" — needs to be checked
   against INDstocks' actual API reference (not available to search from
   this environment). Specifically: whether their instrument-lookup endpoint
   accepts a filter/segment parameter that returns MCX commodity contracts,
   and what shape (`scrip_code`, `exchange_segment` value, lot size, etc.)
   those rows take, since every existing INDmoney adapter method
   (`get_holdings`, `get_positions`, `get_quote`) would need the same
   `exchange_segment` parsing pattern extended, not replaced.
3. **Historical/live candle availability for MCX** via the tiered fetcher
   (`data_fetcher.py`) — yfinance has some commodity futures tickers (e.g.
   `CL=F` for WTI crude) but they are US-exchange contracts, not MCX-specific
   contracts, so the existing 3rd-tier yfinance fallback would not be a
   like-for-like substitute if Zerodha/INDmoney MCX access is unavailable —
   this needs a decision on whether an approximate global-proxy fallback is
   acceptable for MCX or whether "no fallback" is preferable to a misleading
   one.

## 3. Scoped implementation plan (for a follow-up task, not this pass)

If both of the above are confirmed feasible:

- Add `"MCX"` handling to `_to_zerodha_symbol()`/`_to_yf_symbol()` in
  `data_fetcher.py` for the commodity contracts actually traded
  (CRUDEOIL/CRUDEOILM, NATURALGAS/NATGASMINI, GOLD/GOLDM, SILVER/SILVERM —
  confirm exact Zerodha trading-symbol conventions for mini/micro contracts).
- Extend `require_broker()`'s `BrokerClient` implementations
  (`zerodha_web.py`, `jugaad.py`) with an `exchange` parameter on `orders`/
  `quote`/`historical_data` where Kite Connect's API supports it, defaulting
  to the current NSE-only behavior so no existing caller breaks.
- Extend `src/brokers/indmoney.py`'s instrument resolution to parse MCX-shaped
  `exchange_segment` values (e.g. `"MCX_FO"`) the same way `"NSE_EQ"` is
  parsed today, once the exact INDstocks response shape is confirmed.
- No `monitor.*` schema migration needed — `exchange` is already free-text.
- New tests would need synthetic MCX order/position/quote fixtures mirroring
  the existing NSE ones in `conftest.py`.

This plan is intentionally not started — per the task, Priority 5 is scoped
as investigation only in this pass.
